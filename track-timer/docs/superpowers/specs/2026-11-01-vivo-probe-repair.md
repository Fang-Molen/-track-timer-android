# vivo 诊断版修复范围

用户在 V2324HA / Android 15 上复测仍然听不到声音，录像约 30 fps。原始报告证明 48 次对时完成、两段请求 60 fps 但传感器与编码均约 30 fps、四段录音无提示音候选；用户确认未听到声音。没有新的复测 ZIP。

目标是交付 0.1.1-probe APK，改正已查明的播放通道与音量诊断不匹配，按 Android 会话 API 的要求提前提交帧率，并提供下一次真机排查缺失的证据。不能声称未测试的硬件问题已经解决。

- 保留 Kotlin 原生界面、Android 8+ / minSDK26、targetSDK35、48 kHz 优先录音、150 ms / 1800 Hz 测试音、60/30 fps 普通录像和既有校准协议。
- 播放改为媒体用途，与媒体音量和音量键一致；申请短暂音频焦点，记录拒绝、实际音量/静音、输出设备、播放帧进度，不擅自改变系统音量或绕过勿扰。
- 增加同一播放实现的无麦克风试听，区分播放故障与录音同时运行的影响；前后台切换、错误和结束均释放资源。导出保留失败诊断。
- API28+ 在 SessionConfiguration 中设置与重复请求相同的帧率参数；API26/27 保持兼容路径。配置必须检查预览和编码两类输出的帧时长，不能仅根据 MediaRecorder 声明选择60。
- 记录请求范围、实际 AE 范围、传感器帧时长、控制模式、会话路径、是否支持提前配置帧率。持续30fps须明确提示未达到请求帧率。
- 时间戳、视频映射和总计时精度仍标为未验证；不改检测阈值，不加高速录像、成绩计算或无线协议功能。
- 在既有私有仓库发布源码与单独可下载的新版 APK，保留原README及旧版交付物；不上传用户原始音视频。

参考：AOSP android-15.0.0_r1 AudioAttributes.toVolumeStreamType 将 USAGE_ASSISTANCE_SONIFICATION 映射为 STREAM_SYSTEM；SessionConfiguration.setSessionParameters 建议用与首个请求相同模板提供初始会话参数。现有日志不足以证明设备降至30fps的最终原因。
