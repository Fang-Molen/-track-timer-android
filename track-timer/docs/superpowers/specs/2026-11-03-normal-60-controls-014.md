# 0.1.4 普通60帧配置对照

用户明确授权继续修改并交付APK，测试VIDEO_RECORD输出用途与手动传感器帧周期。既有真机证据：普通720p/1080p纯采集与录像均约30fps；720p受限高速视频经原MP4独立解码约119.715fps，元数据帧号每次跨4。普通60未解决，不能声称安卓统一限制或厂商封锁。

同一后置相机，一键顺序运行9项，每项10秒且全程无预览：720p四组合(DEFAULT+AE、VIDEO_RECORD+AE、DEFAULT+手动、VIDEO_RECORD+手动)，1080p同四组合，再运行已存在的720p120高速录像。约2分钟。旧模式保留手动菜单，取消/后台/错误恢复行为保留，小日志导出不变。

显式录像用途仅在API33+且相机声明支持VIDEO_RECORD=3时选择；在建会话前对唯一录像OutputConfiguration设置，不对高速会话修改用途。无支持则明确失败、不回退。

手动模式要求MANUAL_SENSOR能力、AE_OFF和必要请求键、有效曝光/ISO/最大帧周期范围。请求AE_OFF、CONTROL_MODE_AUTO（保留AF/AWB）、曝光8,000,000ns、帧周期16,666,667ns、ISO800（超出设备范围时夹到边界并记录）。不满足8ms曝光/帧周期时不选择。仅公开API，不写厂商私有参数。固定曝光可能偏暗/偏亮，界面说明仅作帧率诊断。记录请求值与每帧实际AE/ISO/曝光/帧周期，不能把设置已提交当作生效。

高速报告明确区分元数据样本速率、视频样本速率和帧号跨度推算。保留captureFps兼容字段但明确语义；高速sensorFps、captureFpsAchieved及requestedFpsAchieved为未知(null)，不把每秒30次元数据当作30fps录像，也不凭视频120就证明逐帧传感器映射。高速不根据稀疏元数据估算丢帧。>=5秒、无错误/取消的视频PTS达标单独标记videoRateReached，精度/逐帧映射仍false。普通60要求传感器和编码端均达标；汇总分开显示普通达标数与高速视频结果。

保持包名cn.tracktimer.app、min26/target35、旧签名，versionCode5 / 0.1.4-probe。发布到唯一现有仓库，不上传原始用户画面或日志。不修改音频或训练计时功能。
