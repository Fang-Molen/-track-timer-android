Approaches considered: MediaRecorder normalized MP4 PTS alone cannot determine its absolute time origin; fitting an arbitrary offset can hide a clock mismatch. External flash calibration is useful for optical/system validation but is a later experiment; this version measures timestamp correspondence only.

Record original codecPTS, output-observation monotonic times, sensor metadata/frame numbers, recording start/end elapsedRealtime, EOS/completion errors, camera timestamp-source declaration, actual frame counts/gaps and normalized MP4 PTS. No fitted offset may create success. Require all metadata sensor times <= their callback elapsed times and age<=2seconds. Strictly increasing positive timestamps, full EOS, error-free/noncancelled measurement and>=90% requested video rate for>=5seconds are separate gates.

Verify saved MP4 sample count and every PTS against rawPTS-firstRawPTS within2microseconds before treating file/clock relation as observed. Expose firstRawPTS as the file-to-local-clock origin only when those checks and sampled sensor correspondence succeed. Metadata is sparse in high-speed mode: sampled alignment is not proof of every frame's exposure, physical accuracy or electronic timing equivalence. Keep precisionVerified and captureToEncodedMappingVerified false. Never synthesize sensor timestamps or certify acoustic start. Retain existing double-phone calibration workflow separately; report app clockSession so exported network logs can be associated without silently applying a stale offset.
