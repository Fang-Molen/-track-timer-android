# Field signal timing 0.1.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans inline, one independent final review.

**Goal:** Deliver two-phone signal start, high-speed finish capture and exact-index manual finish times for track testing.
**Architecture:** Core race coordinator/wire API extends existing SyncServer without changing PROBE. Android receiver controls synchronization and race messages; separate role/review activities reuse CameraProbe with bounded long capture. Saved race journals join immutable signal, camera report and calibrations.
**Tech Stack:** Kotlin Android Camera2/MediaCodec, sockets, MediaMetadataRetriever API28, JUnit/Robolectric.
**Spec:** ../specs/2026-11-04-field-signal-016.md

## Global Constraints
- Version7/0.1.6-field, min26/target35, field finish/review28+, existing signing identity/repo.
- Signal event is timing zero; cue latency uncalibrated; no microphone field flow or FAT claim.
- READY only with producing recorder and good session-bound sync; stale/duplicate messages cannot create a second signal.
-180s maximum, bounded frames and storage, exact-index replay uses raw timestamps.

## Review Focus
- Race/session changes, duplicate/replayed commands, stale readiness and missing ACK must not create a valid-looking result.
- Cancellation/background/late callbacks must not arm or reopen hardware; partial resources and files handled honestly.
-180s240 capture must not retain old6000/10000 limits or silently truncate timestamp arrays.
- MP4 rounding cannot feed elapsed time; displayed frame/index must equal saved result and historical sessions stay bound.
- Cue failure, missing post sync, interrupted trial and camera errors must be visible and cannot be presented as verified FAT.
