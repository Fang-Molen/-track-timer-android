# 跑道计时 · 跑道实测版 0.1.8

两台安卓分别作为起点和终点，以电子发令事件为零点，终点持续高速录像后手动逐帧判线，保存多人成绩及历史场次。**声音输出延迟未校准，整套精度未验证，不是正式比赛电计时。**

[下载APK](../deliverables/track-timer-0.1.8-field.apk) · [安装与跑道操作](../deliverables/RELEASE-0.1.6.md) · [验证记录](verification/VALIDATION-0.1.8.md)

本次按视频比例放大预览和逐帧画面，并修正Android高速带预览的批次元数据识别；符合模式的历史报告可在内存重新检查。保持原有时钟匹配和录像完整性门槛。[0.1.8修复说明](../deliverables/RELEASE-0.1.8.md)。0.1.7画面方向、比例和黑屏已由用户确认修复；本版仍需真机复测。

同一局域网，起点开启服务，终点填IP/六位码。终点完成48轮对时、相机开始产出帧后才允许起点发令。默认720p120，可选240或关闭预览；不支持的明确模式不降档。最长180秒包含准备时间。起点Android8+，终点和逐帧审阅Android9+。

发令消息携带场次及会话，起点保存不变时间戳，终点重复查询/回执。等待时每10秒刷新对时；短期READY心跳过期禁用发令。停止录像后再次对时；没有结束确认、时差变化过大或中断时只保留复核状态。视频按确切帧索引解码，成绩使用对应原始编码PTS，不用有量化偏差的MP4播放PTS。所有precisionVerified仍为false。

V2324HA的0.1.5报告已观察到约119.57/239.23帧，稀疏元数据与原始编码时间对齐；文件PTS存在约0.68/3.17ms最大偏差。它支持继续做本版的软件闭环，0.1.7带预览120帧也已录得，批次校准离线修正通过；长录像、240帧带预览及整套物理精度仍待验证。

## 导出数据

|文件|内容|
|---|---|
|field_race_*.json|场次、历史时钟会话、前后对时、起点事件、相机报告引用、多人成绩|
|field_start_*.json / field_cue_*.json|起点电子事件及提示音播放诊断|
|camera_*.json / video_*.mp4|完整帧时间戳、相机/编码诊断与无音轨录像|
|device/calibration/comparison/audio/playback报告|保留的旧诊断功能|

首页小日志导出不含音视频；完整导出包含原始媒体。没有自动清理。所有*Ns单位纳秒，createdAtUnixMs仅用于辨认记录。历史场次使用保存时的会话，不能套用当前新会话校准。

## 本地构建

JDK21、Android SDK35、Build Tools35.0.0。Android Studio打开本目录，未提交local.properties指向本机SDK：

```sh
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

APK在app/build/outputs/apk/debug/app-debug.apk。固定Gradle8.11.1、Kotlin2.1.10、AGP8.9.1。测试覆盖真实loopback TCP、会话/心跳/回执、原始帧时间换算、持久化和Android界面/权限；软件测试不能代替手机跑道、曝光或声音校准。

后续：根据本版双机实测日志调整兼容性；参考电计时与声学校准；自动识别、行进间冲刺、成绩CSV与多机发令。旧诊断说明见各历史RELEASE/VALIDATION文件。以下保留早期故障背景。

## 0.1.1 真机问题修订

针对 vivo V2324HA 上“听不到发令音、实际约30fps”的反馈：测试音由系统提示音用途改为媒体用途，增加独立试听、焦点和播放进度诊断；相机在 Android 9+ 创建会话时提前提交帧率，选模式同时检查预览与编码输出。报告新增实际 AE 范围、帧时长和控制模式，未达到请求帧率时明确提示。

已发现并修正代码配置问题；该设备的实际可听声音、稳定60fps及总计时精度仍需安装新版后复测。这次没有加入跑步成绩功能。

## 0.1.2 相机兼容测试（历史说明）

设备自带相机能拍60帧与第三方App当前配置只能输出30帧并不矛盾。0.1.1报告显示720p双输出已提交并返回[60,60]，采集和编码仍约30.002fps。因此本版比较实际可调用的不同配置；没有把请求值、设备声明或文件名当成实测帧率。

下拉菜单按这个顺序测试，每种录10秒，界面会列出各模式最近一次结果：

1. **1080p · 请求60帧 · 含预览**（默认）。
2. **720p · 请求60帧 · 仅录像**。录制时不显示预览，是有意隔离预览输出，不是录像失败。
3. **1080p · 请求60帧 · 仅录像**。
4. **720p · 请求60帧 · 含预览（对照）**，与旧配置比较。
5. 若以上仍30帧，再选 **720p · 请求120帧 · 高速实验**。仅在设备声明支持该尺寸和固定120范围时使用专用高速会话及批量请求，不支持则保存明确失败报告。高速模式预览可能低于录像帧率，需看保存视频的测量结果；逐帧时间映射仍未标定。

“自动选择60或30帧”保留旧版兼容行为；其余明确指定的模式不静默改成其他分辨率/帧率。模式未达到请求值或启动失败，也请导出小日志。小日志包含历史JSON，不含MP4/WAV，不保证无限历史下始终小于32MiB。

本版没有调整声音检测阈值，没有加入跑步成绩。实际60/120fps和计时精度仍需真机报告验证。
