# 跑道计时 · 设备验证版 0.1.2

这是 Android 原生应用的第一阶段：在现有手机上采集真实的设备、双机校准、视频和音频诊断数据。**本版尚不输出跑步成绩，也未验证达到 ±0.05 秒精度。**

## 安装与使用

支持 Android 8.0（API 26）及以上。两台手机安装同一个 `track-timer-0.1.2-probe.apk`。这是开发调试签名安装包，安装时按系统提示允许当前来源安装；无需注册或付费。

1. 每台打开 App，点「检测并保存设备报告」。这一步记录实际可调用的相机模式，不以自带相机的慢动作设置为依据。
2. 两台加入同一 Wi-Fi，或一台开启热点、另一台连接。第一次先把两台放在一起。
3. 起点手机点「作为起点：开启校准服务」，保持 App 在前台。终点手机填写它显示的 IPv4 地址和六位配对码，执行校准。端口固定为 19119；如果显示多个地址，选择 Wi-Fi/热点所在网络的地址。
4. 每台先点「只试听发令音（不录音）」确认能听到“滴”声，再点「测试发令音与麦克风」。试听不请求麦克风权限。音量键调整媒体音量，App 不自行修改系统音量；首次测试使用本机扬声器并保持环境安静。录像默认测试1080p60；可按下方兼容测试步骤切换模式，固定手机、光线充足，按提示授权。
5. 权限已授予后，再做一次录像和录音同时进行的测试；查看采集帧率、保存视频帧率、最大帧间隔与音频时间戳数量。
6. 在同一次 App 会话内，间隔一段时间再校准一次，观察时差变化。过程中关闭起点服务或重启 App 会更换会话标识，不再直接比较不同会话。
7. 排查帧率时优先「仅导出日志 ZIP（小文件）」，只打包JSON和说明。需要原始音视频时选择「导出诊断报告 ZIP」；两种方式都保留本机原始文件。

手机热点可能限制设备互访；校园或公共 Wi-Fi 也可能开启客户端隔离。连接失败时先核对地址和配对码，再尝试一台手机开热点。App 不使用互联网服务器，不保证隔离网络中的连接。

本版测试需保持 App 在前台；离开页面会停止录像、录音和校准服务。已完成文件仍保留在本机。查看/导出不会自动清理历史录音录像；卸载或清除应用数据会删除它们。

## 怎么理解结果

- 「可请求 60 fps」是能力枚举；「采集帧率」与「编码视频帧率」才是这次测试的实际观测。低照度或发热时可能下降。
- 普通录像接口只暴露 30 fps 时，会请求 30 fps 并明确显示。相机自带应用支持 60 fps，不一定代表第三方接口支持。
- 网络时差为**起点端单调时钟减去终点端单调时钟**；估计范围只反映短时通信模型，不是整套计时系统的精度。
- 相机采集时间戳、视频 PTS 和音频硬件时间戳会保留。采集到编码帧的对应关系、声学固定延迟都还需要真机标定。
- 音频检测结果叫「候选」：环境里相似的声音也可能触发它。缺少硬件时间戳时不会用按钮点击时间补成“准确发令时间”。
- 本版不会把模拟器或单元测试结果当作手机的实际精度证明。

## 导出的数据

| 文件 | 内容 |
|---|---|
| `device_*.json` | 型号、系统版本、相机配置、音频能力和编码器 |
| `calibration_*.json` | 48 次四时间戳交换、偏移区间、单调时钟会话、前后漂移诊断 |
| `camera_*.json` | 相机原始时间戳、曝光、滚动快门参数、视频采样 PTS 与帧率统计 |
| `video_*.mp4` | 完成保存的短视频，无音轨 |
| `audio_*.json` | 录音硬件时间戳、播放请求时刻、声音候选与音频路由；新增 playback 播放诊断 |
| `playback_*.json` | 不录音的独立试听；实际媒体音量、焦点、路由和播放进度 |
| `audio_*.wav` | 单声道 16-bit PCM 麦克风录音 |

`playback.outputTimestampNs` 属于 Android MONOTONIC 时钟，已单独标注，不能与 BOOTTIME 录音/系统时间直接相减。输出播放进度也不证明声音已经被听到。

所有 `*Ns` 字段以纳秒计；`createdAtUnixMs` 仅供辨认报告时间，不能用于运动计时。手机时钟会话变化后不要混用旧校准。

## 本地构建

安装 JDK 21、Android SDK Platform 35 和 Build Tools 35.0.0。可用 Android Studio 打开本目录。

创建未提交的 `local.properties`，内容为 `sdk.dir=你的AndroidSDK绝对路径`，然后运行：

```sh
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。Gradle Wrapper 固定在 8.11.1；23 项核心测试使用真实本地 TCP 连接、手算时间样本和合成音频信号。另有 Robolectric Android 框架测试，覆盖界面、权限、媒体音量/焦点、取消、相机会话参数、预览帧率限制，以及 Android 8 兼容路径；测试数量和结果见 verification/VALIDATION-0.1.2.md。

## 0.1.2 相机兼容测试

设备自带相机能拍60帧与第三方App当前配置只能输出30帧并不矛盾。0.1.1报告显示720p双输出已提交并返回[60,60]，采集和编码仍约30.002fps。因此本版比较实际可调用的不同配置；没有把请求值、设备声明或文件名当成实测帧率。

下拉菜单按这个顺序测试，每种录10秒，界面会列出各模式最近一次结果：

1. **1080p · 请求60帧 · 含预览**（默认）。
2. **720p · 请求60帧 · 仅录像**。录制时不显示预览，是有意隔离预览输出，不是录像失败。
3. **1080p · 请求60帧 · 仅录像**。
4. **720p · 请求60帧 · 含预览（对照）**，与旧配置比较。
5. 若以上仍30帧，再选 **720p · 请求120帧 · 高速实验**。仅在设备声明支持该尺寸和固定120范围时使用专用高速会话及批量请求，不支持则保存明确失败报告。高速模式预览可能低于录像帧率，需看保存视频的测量结果；逐帧时间映射仍未标定。

“自动选择60或30帧”保留旧版兼容行为；其余明确指定的模式不静默改成其他分辨率/帧率。模式未达到请求值或启动失败，也请导出小日志。小日志包含历史JSON，不含MP4/WAV，不保证无限历史下始终小于32MiB。

本版没有调整声音检测阈值，没有加入跑步成绩。实际60/120fps和计时精度仍需真机报告验证。
