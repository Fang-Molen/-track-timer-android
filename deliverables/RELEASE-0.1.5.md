# 0.1.5-probe · 120/240帧时钟校准小测试

[下载APK](track-timer-0.1.5-probe.apk)。与旧版同包名和签名，直接覆盖安装，保留已有报告。

## 先做这个测试

1. 确认页首版本0.1.5-probe。此轮一台手机即可。
2. 手机固定、光线充足，点击 **一键校准120/240帧（约30秒）**。
3. 保持前台，等待720p120帧、720p240帧各10秒完成。没有预览是预期行为；240不支持或失败也会保留120结果，不静默替换帧率。
4. 点击 **仅导出日志 ZIP（小文件）**，发送ZIP。无需先传大视频。

如同时带来两台手机，可先按现有“两台手机对时”完成48次校准，再在终点手机运行上述测试，一起导出日志。同一App会话的clockSession用于关联；本版不会自动套用旧对时偏移生成跑步成绩。

## 这次测什么

- 120/240实际视频帧率与帧间隔。
- 编码器原始时间戳是否与相机返回的传感器时间戳直接吻合；Android13+显式选择传感器时间基准。
- 保存后的MP4是否完整保留帧数与相对时间。视频按实际采集间隔保存，正常速度播放，不人为拉长为慢动作。

新版使用MediaCodec Surface编码路径，保留封装MP4前的原始时间戳，再将第一帧归零写入MP4。既有MediaRecorder模式仍可作为对照。新编码路径的设备兼容性与240帧能力需要此次真机运行确认。

“采样时间对齐”要求至少5秒、30个元数据样本、覆盖至少80%编码时间跨度；重叠范围内每个元数据样本均须直接匹配编码时间戳（容差2微秒），且相机声明REALTIME时钟。编码结束、无错误/取消、实际视频率达到请求90%及MP4每帧时间保存也分别检查。匹配容差只处理时间戳量化，不代表光学或总计时误差2微秒。

高速元数据可能每4或8帧返回一次。因此“采样时间对齐”不等于每一帧独立曝光或整套电计时精度已验证；precisionVerified保持false，不插值伪造传感器时间戳。
